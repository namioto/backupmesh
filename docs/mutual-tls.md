# Mutual TLS configuration

BackupMesh exposes a remote TLS 1.2 or TLS 1.3 Control API that requires a client certificate while keeping the loopback HTTP endpoint for the Windows tray app. On first start, the Storage Agent creates a private pairing CA whose key is protected with Windows DPAPI. It uses that CA to issue its in-memory server certificate and the separate Source certificates exported by the tray app.

The remote endpoint is enabled by default on port `7443`. Its certificate includes `localhost`, the Windows computer name, and loopback addresses. Add every DNS name or IP address used by Sources to `MutualTls:ServerNames`; the first non-localhost entry is also written to new pairing bundles as the Control API address. A manually supplied PKCS#12 certificate remains supported through `ServerCertificatePath` and `ServerCertificatePassword`, but automatic issuance is recommended because pairing bundles already trust the pairing CA.

On each Source Agent, use an `https` `controlEndpoint` whose host appears in `ServerNames`, then apply the tray-generated pairing bundle with `backupmesh-agent apply-pairing`. The command configures all three absolute TLS paths and changes `agent.id` to the UUID embedded in the client certificate Common Name. The CA validates the Storage Agent and the certificate/key identify that Source. The identity-bound bearer token provides an additional application-level credential.
