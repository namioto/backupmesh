# Mutual TLS configuration

BackupMesh exposes a remote TLS 1.2 or TLS 1.3 Control API that requires a client certificate while keeping the loopback HTTP endpoint for the Windows tray app. On first start, the Storage Agent creates a private pairing CA and a separate server certificate; their private keys are protected with Windows DPAPI. The pairing CA signs each Source certificate exported by the tray app. Kestrel validates Source certificates against this private CA in memory, so the CA is never installed in the Windows trust store.

The remote endpoint is enabled by default on port `7443`. Its pinned, self-signed server certificate includes `localhost`, the Windows computer name, and loopback addresses. Add every DNS name or IP address used by Sources to `MutualTls:ServerNames`; the first non-localhost entry is also written to new pairing bundles as the Control API address. A manually supplied PKCS#12 certificate remains supported through `ServerCertificatePath` and `ServerCertificatePassword`.

For a new Source, the tray app creates a cryptographically random one-time code that expires after ten minutes and displays the Storage endpoint and SHA-256 server-certificate fingerprint. Run `backupmesh-agent pair` with those three values. The Source pins the fingerprint before it transmits the code, then receives an identity-bound credential and client certificate. A code is removed atomically after one successful exchange. The legacy file bundle command remains temporarily available for migration, but new connections should not create transferable private-key files. No certificate is installed in the Windows global trust store.

The dynamically allocated rest-server repository endpoints also use TLS and the same pinned Storage server certificate. The Source passes that certificate to restic through `RESTIC_CACERT`, so repository traffic is encrypted without depending on the Windows or Linux system trust store. The Storage service writes the PEM key only while starting rest-server, removes it as soon as the listener is ready, and removes remnants from interrupted starts on the next service launch. The Windows installer restricts `%ProgramData%\BackupMesh` to LocalSystem and local administrators.
