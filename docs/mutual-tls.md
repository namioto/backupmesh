# Mutual TLS configuration

BackupMesh exposes a remote TLS 1.2 or TLS 1.3 Control API that requires a client certificate while keeping the loopback HTTP endpoint for the Windows tray app. On first start, the Storage Agent creates a private pairing CA and a separate server certificate; their private keys are protected with Windows DPAPI. The pairing CA signs each Source certificate exported by the tray app. Kestrel validates Source certificates against this private CA in memory, so the CA is never installed in the Windows trust store.

The remote endpoint is enabled by default on port `7443`. Its pinned, self-signed server certificate includes `localhost`, the Windows computer name, and loopback addresses. Add every DNS name or IP address used by Sources to `MutualTls:ServerNames`; the first non-localhost entry is also written to new pairing bundles as the Control API address. A manually supplied PKCS#12 certificate remains supported through `ServerCertificatePath` and `ServerCertificatePassword`.

On each Source Agent, apply the tray-generated pairing bundle with `backupmesh-agent apply-pairing`. The bundle pins the Storage server certificate, configures the client certificate and key, and changes `agent.id` to the UUID embedded in the client certificate Common Name. The Storage Agent validates that certificate against its private pairing CA and then binds its Common Name to the independent bearer credential. No Windows certificate installation prompt is involved.
